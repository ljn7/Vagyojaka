# Vagyojaka (ASR Post Editor)

This tool facilitates editing transcripts that are generated by ASR (Auto Speech Recognition) models.

## Build

### Prerequisites

| | |
|---|---|
| **Qt 6** | Base, Multimedia and MultimediaWidgets. [Download](https://www.qt.io/download). |
| **CMake** | 3.21 or newer. |
| **C++ compiler** | Matching the Qt kit you installed (MSVC, MinGW, GCC or Clang). |
| **Python 3** | Optional, on PATH. Only needed for the edit alignment, translation and transcript generation helpers. |

Dependencies (libgit2, FFTW3, FFmpeg) are resolved by CMake. On Windows they come
from vcpkg, on Linux and macOS from the system package manager.

Set `QTDIR` to your Qt kit so CMake can find it, for example
`C:\Qt\6.8.1\msvc2022_64` or `~/Qt/6.8.1/gcc_64`.

### Windows

```shell
git clone https://github.com/ljn7/Transcriptor.git
cd Transcriptor

# One time setup
git clone https://github.com/microsoft/vcpkg C:\vcpkg
C:\vcpkg\bootstrap-vcpkg.bat
setx VCPKG_ROOT C:\vcpkg
setx QTDIR C:\Qt\6.8.1\msvc2022_64

# FFmpeg: download a shared build from
# https://github.com/BtbN/FFmpeg-Builds/releases, extract it anywhere,
# and point FFMPEG_ROOT at the folder containing include\ and lib\
setx FFMPEG_ROOT C:\ffmpeg

# Build (run from a Developer Command Prompt for the MSVC preset)
cmake --preset windows-msvc
cmake --build --preset windows-msvc
```

vcpkg installs libgit2 and FFTW3 automatically on the first configure, driven by
`vcpkg.json`. Use the `windows-mingw` preset instead if you are on a MinGW Qt kit.

To have vcpkg build FFmpeg from source rather than using a prebuilt one, configure
with `-DVCPKG_MANIFEST_FEATURES=ffmpeg` and skip `FFMPEG_ROOT`. This is considerably
slower.

### Linux

```shell
sudo apt install build-essential cmake ninja-build pkg-config \
     libgit2-dev libfftw3-dev \
     libavcodec-dev libavformat-dev libavutil-dev libavdevice-dev

cmake --preset linux
cmake --build --preset linux
```

### macOS

```shell
brew install cmake ninja pkg-config libgit2 fftw ffmpeg

cmake --preset macos
cmake --build --preset macos
```

### Tests

```shell
ctest --preset linux        # or windows-msvc, windows-mingw, macos
```

| Suite | Covers |
|---|---|
| `dictionary` | On-disk binary search, prefix completion, the in-memory overlay |
| `serializer` | Transcript XML round trip, timestamp parsing, malformed input |
| `edits` | Merging lines, shifting timestamps, renaming speakers |
| `analysis` | Word normalisation and spell check classification |

Tests are plain executables that return non-zero on failure, so they need no test
framework. Set `-DVAGYOJAKA_BUILD_TESTS=OFF` to skip building them.

### Other presets

`cmake --list-presets` shows everything available. Each platform has a `-debug`
variant. Build output lands in `build/<preset>/output/`.

Qt Creator picks the presets up automatically when you open `CMakeLists.txt`.

### Dictionaries

The spell check word lists are compiled at build time from `editor/wordlists/*.txt`
into sorted `.dict` files under `build/<preset>/output/wordlists/`. The application
memory-maps and binary searches them, so they are never loaded into memory and never
sorted at run time.

This means `output/wordlists/` has to travel with the executable when you package a
build. On macOS the build places them inside the bundle at `Contents/Resources/wordlists`
automatically.

### Deployment

`windeployqt` (Windows) or `macdeployqt` (macOS) is needed to produce a
redistributable build. Qt Creator handles this for local runs.

## Contributing

Run `clang-format` before committing. The project style lives in `.clang-format`,
and `.clang-tidy` holds a deliberately narrow set of correctness checks.

CI runs both, but advisory only: this codebase predates any linting, so the existing
findings would otherwise block every pull request. Tighten them to blocking once the
backlog behind each enabled check is cleared.
